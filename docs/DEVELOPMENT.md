# Зверушка на рабочем столе (Desktop Pet)

Настольный питомец для Windows: пиксельная зверушка (**хомячок**,
**скотч-терьер** или **котик** — на выбор в меню) бегает по панели задач,
реагирует на мышь, спит на подушке, злится, скучает и раз в час шлёт нежную
фразу поддержки в облачке. Есть **система прогресса**: опыт, уровни с
титулами, журнал достижений и **три мини-игры** (см. §2.2).
**Работает на ПК без установленного Python** — готовая папка в `dist\`
(см. §1).

> **Документ поддерживается в актуальном состоянии.** Любое изменение
> поведения, файлов или сборки отражается здесь в том же коммите/сессии.
> Последнее обновление: 23.11.2026.

---

## 1. Запуск

- **Готовое приложение (нужен только Windows, Python НЕ требуется)**:
  `run.bat` или напрямую `dist\Zverushka\Zverushka.exe`. Раздача —
  **папка (onedir)**: один запускаемый файл `Zverushka.exe`, рядом —
  `settings.json` (настройки и прогресс, создаётся при первом запуске),
  `assets\` (спрайты, редактируемый `assets\sprites\phrases.json`
  с фразами облачка) и `_internal\` (интерпретатор Python, PySide6,
  numpy — упакованы PyInstaller'ом, проверено запуском без доступа
  к `C:\pylib`).
- **Из исходников**: `python app.py` (нужен Python 3.13 + зависимости,
  см. §6). Зверушка живёт в системном трее, второй экземпляр не запустится
  (мьютекс `DesktopPet_Zverushka_Singleton`).

## 2. Что делает зверушка (поведение)

| Условие / действие пользователя | Реакция зверушки |
|---|---|
| Просто работаете | Гуляет влево-вправо по «полу» (по умолчанию — верхняя кромка панели задач), иногда сидит, иногда бежит (с пылью из-под лап); сидя, иногда меняет настроение — довольная или игривая мордочка |
| ~4 минуты без внимания (кликов/ховера) | Засыпает на подушке (шанс растёт со временем), спит 4–8 минут, над ним летят «Zzz» |
| Клик по зверушке | Радуется (поза «в руках» сбрасывается автоматически) |
| Клик во сне | Просыпается с потягушками и удивлённой мордой |
| 5+ кликов за 5 секунд | Злится (дым из ушей) |
| Двойной клик | Смущается и подпрыгивает |
| Навести курсор на 3 секунды | Умиляется одной спокойной позой (без мельтешения), сердечки; ховер НЕ вызывает грусть, даже если зверушка до этого скучала |
| Перетащить мышью | «Поднятая» поза + плавное покачивание корпуса от движения мыши (держишь неподвижно — висит спокойно); куда отпустили — там и гуляет (уровень «пола» меняется) |
| Отпустить после переноса **над открытым окном** (выше его верхней кромки) | Падает вниз и **приземляется на кромку этого окна** — гуляет по ней; окно закрыли, сдвинули или развернули на весь экран — спрыгивает обратно на панель задач. Посадка сопровождается радостным прыжком |
| Отпустить **на фоне окна** (ниже его кромки), над рабочим столом или над развёрнутым окном | Падает вниз на **панель задач** — зверушка всегда падает только вниз, никогда не «перелетает» вверх на окно |
| 5 мин без внимания | Сонная мордочка; 10 мин — скучает |
| Примерно раз в час (±10 мин) | Всплывающее облачко с нежной заботливой фразой (`assets/sprites/phrases.json`); не во сне и не «в руках» |
| Край экрана при ходьбе | Разворачивается, любопытничает (звёздочка) |

### 2.1 Система прогресса (RPG-lite)

Зверушка растёт вместе с вами. Прогресс хранится в `settings.json`
(секция `progress`) и переживает перезапуски и смену питомца.

**Опыт (XP):**

| Источник | XP |
|---|---|
| Клик / двойной клик | +2 / +3 (анти-фарм: не больше 30 XP за 10 мин кликами) |
| Обнимашки (ховер 3 с) | +5 |
| Облачко-фраза (раз в час) / «Подбодри меня» | +10 / +4 |
| Каждые 5 минут вместе | +2 |
| Фокус-бонус: 25 минут без кликов | +15 (и тёплая фраза) |
| Каждые 20 000 px пути лапами | +1 |

**Уровни и титулы:** порог до следующего уровня растёт (ур. 2 — 50 XP,
ур. 5 — 500, ур. 10 — 2250). Титулы: Новичок → Знакомец (ур. 2) →
Дружок (4) → Компаньон (6) → Напарник (9) → Хранитель стола (12) →
Легенда рабочего стола (15). Новый уровень — облачко-поздравление и
салют из частиц.

**Журнал достижений** (меню «Прогресс»): 26 ачивок — от «Первого
контакта» до «Месяц дружбы» (стрик 30 дней), «Знакомство со всеми»
(побывать каждой зверушкой) и серии всех трёх игр. Там же — стрик дней,
суммарный путь лапами и статистика игр.

### 2.2 Мини-игры (меню «Игры»)

У каждой игры свой кулдаун 5 минут (анти-фарм), награда — 2 XP за очко
(учитывается до 15 очков за игру), рекорды и ачивки в журнале. Во время
игр клики принимаются и вне тела зверушки — но только в игровой зоне
(см. §4). На паузе игры не запускаются. **Любую игру можно прервать
досрочно крестиком** в правом верхнем углу экрана (очки, набранные
к этому моменту, засчитываются).

- **Догонялки** (20 с): зверушка хаотично носится ПО ВСЕМУ ЭКРАНУ,
  убегая к случайным далёким точкам — поймайте её кликом! Пойманная
  зверушка замирает, умиляется (сердечки), дразнится фразой
  («Не поймаешь!», «Слишком медленно!»...) и через ~2 с снова убегает.
  После игры остаётся на том уровне, где бегала. Ачивки за 5/10/15
  попаданий за игру и за 5/20 игр.
- **Лакомства** (30 с): по «полу» подсвечивается светлая пунктирная
  **дорожка** (игровая зона) с пульсирующими кругами-подсказками —
  кликайте по ней: на месте клика появляется печенька (максимум 3
  одновременно), зверушка бежит к ближайшей и съедает её с умилением.
  Ачивки: первое лакомство, 8 за игру, 30 суммарно.
- **Пузырьки** (30 с): вокруг зверушки всплывают мыльные пузыри — лопайте
  их кликом. Зверушка наблюдает и радуется каждому лопнувшему. Ачивки:
  первый пузырёк, 15 за игру, 60 суммарно.

### Меню трея (правый клик по иконке)

Пауза · Спрятать / Показать · **На панель задач** (вернуть «пол» на панель
задач) · **Подбодри меня** (облачко с тёплой фразой по требованию) ·
**Что умеет зверушка…** (всплывающая подсказка: какие действия вызывают
какие эмоции и реакции) ·
**Игры** (Догонялки / Лакомства / Пузырьки, см. §2.2) ·
строка статуса (уровень · титул · XP) · **Прогресс** (журнал достижений) ·
Уменьшить/Увеличить фигурку (0.4–2.5×) ·
**Питомец** (Хомячок / Скотч-терьер / Котик — выбор эксклюзивный,
галочка всегда одна) · Выход (завершает
процесс корректно, с сохранением настроек).

### Как зверушка не мешает работе

Окно полноэкранное прозрачное, «насквозь» кликается везде, кроме тела
зверушки (динамический `WS_EX_TRANSPARENT`), не попадает в Alt-Tab
(`WS_EX_TOOLWINDOW`), поверх окон (`topmost`, переустанавливается каждые
~1.5 с). В покое перерисовка редкая (каждый 5-й тик).

## 4. Ключевые решения (почему так)

- **Единый размер во всех позах**: высота контента всегда `base_h`
  (`Pet.body_height()`). Рендер `get_aligned()` обрезает спрайт до
  непрозрачного bbox и масштабирует ровно до заданной высоты, низ контента
  совпадает с линией «пола» — фигурка не «плывёт» на пиксели между кадрами
  и не меняет размер между позами.
- **POSE_SCALE — ручная подгонка отдельных поз** (19.11, заменила
  автонормировку по голове): у терьера и котика позы разнородны
  (сидя / стоя столбиком / лёжа), и выравнивание по высоте контента
  делало лежачие позы визуально крупнее («лежачий котик-гигант»),
  а автонормировка по «розовым щёчкам» сама давала скачки размера.
  Поэтому в `sprites.py` — явная таблица `POSE_SCALE` (питомец → поза →
  коэффициент, например `cat: sleep_0 0.92, react_14 0.78`), подобранная
  визуально по линейкам `_size_*.png`; остальные кадры рендерятся
  с коэффициентом 1.0. На хомячка не действует (его позы однородны).
- **Защита от обрезки краями экрана** (19.11): `Pet.edge_pad()` — половина
  ширины самого широкого кадра при текущем масштабе; `pos.x` (центр
  фигурки) клэмпится с этим отступом и при ходьбе (tick), и при переносе
  мышью (`_handle_drag`). Вертикально при переносе действует
  `Pet.top_clearance()` — максимальная высота рендера среди всех кадров
  (с учётом POSE_SCALE), чтобы самая высокая поза (например, сидящий
  котик) не уходила макушкой за верх экрана. Раньше margin=16 px, и
  широкие/высокие позы обрезались краями.
- **Один кадр — одно изображение**: никаких кроссфейдов (раньше давали
  «двойного хомяка»).
- **Цикл шага — середина ленты** (`S.GAIT = walk_1..walk_6`, один ракурс
  3/4). Кадры переключаются от пройденного пути: 1 кадр на `stride` пикселей
  (ходьба `0.075·h`, бег `0.16·h`) — лапы не скользят. Бег = тот же цикл
  со скоростью ×3.0 + наклон корпуса 6° + пыль. Формулы общие для всех
  трёх питомцев, поэтому скорость и темп анимации у них одинаковые.
- **Спрайты с рукой (react_11/12/13) удалены и не используются** — требование
  пользователя. Перенос мышью — позы `react_02/react_01`.
- **У сгенерированных питомцев (терьер, котик) каждая реакция — ОДИН кадр**
  (`_POSE_OVERRIDES` в sprites.py): их react-кадры — разнородные позы,
  и чередование выглядело мельтешением (19.11). Живость вместо кадров
  дают частицы, покачивание и наклоны корпуса.
- **Перенос мышью без мельтешения**: в позе «в руках» фигурка плавно
  покачивается (маятник от времени + отклик на движение курсора через
  `body_frame`), а у хомяка ещё и перебирает лапками от ПЕРЕМЕЩЕНИЯ
  курсора (`dist / (0.5·base_h)` кадров), а не от тиков таймера — держишь
  неподвижно, зверёк висит спокойно (18.11, раньше `body_frame += 0.6`
  каждый тик давал ~10 Гц дёрганья).
- **Сон**: спрайт сгенерирован (18.11.2026) — хомяк лежит на подушке
  (`sleep_0.png`), «дыхание» — позиционным bob (размер не меняется),
  частицы Zzz. Длительность сна 240–480 с.
- **«Пол» всегда внутри экрана**: `_taskbar_top()` проверяет, что кромка
  панели задач попадает в геометрию экрана, иначе — низ экрана. При старте
  зверушка всегда на панели задач; после переноса — на уровне отпускания.
- **Выход завершает процесс** (`quit_app` = save + `QApplication.quit`);
  простое закрытие окна процесс не убивало (исторический источник
  «зомби»-процессов).
- **Ховер-любовь**: `hover_time` копится только в `hover_tick()` и нигде
  не убывает (18.11 исправлен баг: `tick_face` ежетиково гасил накопленное
  время, поэтому сердечки не появлялись никогда).
- **Поза «в руках» всегда сбрасывается**: у `grabbed` длительность 9999,
  поэтому любой release без переноса вызывает `released_grabbed()`
  (внутри `click()` — первой строкой). Иначе одиночный клик оставлял
  зверушку испуганной навсегда.
- **«Хвост» дабл-клика**: Qt шлёт press → release → dblclick → release;
  последний release приходит при `dragging=False` и только снимает флаг
  `_suppress_dbl_release` — иначе он проглатывал бы следующий одиночный
  клик.
- **Новые питомцы = папка в assets/sprites**: имена файлов общие
  (walk_*, sit_*, react_*, sleep_*, part_*, icon.*), маппинг эмоций в
  `PetSprites._scan` гибко сжимается под имеющиеся кадры, поэтому
  минимально жизнеспособный набор — 4 кадра ходьбы, 2 сидения, сон и
  9 реакций. Листы генерируются image_generation по мастер-референсу
  и режутся `_cut_new_pet.py`; `part_*` (сердечки, zzz, пыль...) —
  универсальные, копируются от хомяка. GAIT берёт середину ленты,
  поэтому 4 кадра ходьбы сохраняются как walk_1..4, а walk_0/walk_5 —
  их копии-заглушки.
- **Мини-игры** (19.11): общий движок (GAMES в app.py: длительность,
  кулдаун, тексты, best-ключ) + три игры (см. §2.2). Во время игр клики
  вне тела зверушки принимает игровая зона: `_game_zone_contains()`
  расширяет область, где окно НЕ click-through (дорожка ±70 px / круги
  пузырьков / крестик прерывания) — за её пределами рабочий стол
  кликается как обычно. Игровые объекты рисуются QPainter'ом (печенька,
  пузырь, вспышка, крестик), спрайты не нужны.
- **Догонялки — бег по всему экрану** (19.11, вторая итерация): цель
  `_tag_target` — случайная точка экрана (в пределах edge_pad /
  top_clearance, не ближе 3·base_h от текущей позиции), зверушка бежит
  к ней со скоростью speed·3, направление мордочки — по знаку dx;
  обычный `pet.move()` во время игры пропускается, «пол» временно равен
  текущему y. После игры `floor_y` принимает уровень, где закончился бег.
- **Крестик прерывания игры**: `_game_close_rect()` — круг r=20 в правом
  верхнем углу экрана (смещение 52 px от углов); учитывается в
  `_game_zone_contains` (не click-through), клик вызывает `_end_game()`
  с засчитыванием набранных очков.
- **Ховер никогда не огорчает, испуг убран вовсе** (23.11): в
  `brain.tick_face` ветки `lonely`/`sleepy` срабатывают только при
  `hover_time <= 0` — раньше после 10 мин без кликов грустная мордочка
  пробивалась даже когда курсор лежал НА зверушке. Реакция испуга на
  резкое движение курсора (`_maybe_scare`/`brain.scare()`) удалена
  полностью по требованию пользователя: подвод курсора — это всегда
  намеренное внимание. Дополнительно исправлена защёлка `loved_fired`:
  она взводится только после РЕАЛЬНОГО показа умиления — раньше, если
  на 3-й секунде ховера лицо было занято сильной эмоцией (злость),
  умиление терялось до конца ховер-сессии.
- **Падение только ВНИЗ** (23.11, вторая итерация): при отпускании после
  переноса `_landing_support(x, y)` ищет окно-опору СТРОГО ниже точки
  отпускания — перебор окон в z-order через `EnumWindows`, для каждого
  `_edge_below(hwnd, x, y)` годит окно, чья верхняя кромка накрывает
  точку по X и лежит ниже неё (допуск +6 px). Если зверушку отпустить
  НАД окном — она падает на его верхнюю кромку и гуляет по ширине окна;
  если отпустить НА ФОНЕ окна (кромка выше точки отпускания) — она
  пролетает мимо него и падает на панель задач, «подлёта» вверх к
  кромке больше нет. `_good_support()` по-прежнему отсекает
  **развёрнутые на весь экран окна** (IsZoomed — иначе зверушка
  садилась бы на верх экрана и «пропадала», баг 23.11) и окна, чья
  кромка выше, чем помещается фигурка (`top_clearance`). Границы окон —
  DWM extended frame bounds (`_window_info`). Падение с гравитацией
  (2600 px/s², cap 1400 px/s), посадка — `brain.landed()` (радость +
  прыжок). `_check_support()` каждые 40 тиков проверяет, что окно ещё
  существует, на месте и не развёрнуто — иначе падение на панель задач.
  `go_to_taskbar()` и старт догонялок сбрасывают опору.
- **Новые эмоции** (23.11): у хомяка задействованы ранее неиспользуемые
  кадры референсов — «расплющенный» (`react_18`, поза crouch; после
  удаления испуга 23.11 не показывается, оставлен про запас) и прыжок
  в воздухе (`react_19`), а также `react_07/09` (игривый) и `react_10`
  (довольный); у котика и терьера догенерированы аналоги
  (`react_06/07/19` у котика — `react_06` стал позой `loved`,
  `react_07/19` у терьера). Появились сидячие смены настроения
  `content`/`playful` в `brain.tick_face`. Размеры новых поз подогнаны
  в `POSE_SCALE` (например, `hamster: react_18 0.52, react_19 0.92`).
  Поза **злости** (показывается при
  частых кликах) перегенерирована 23.11 у всех трёх питомцев: раньше в
  `SIDE.angry` стояли лежачие испуганные `react_14` (котик, терьер) и
  грустно-надутый `react_14` (хомяк) — визуально это читалось как
  испуг/обида, а не злость. Новые кадры: `cat/react_17` и
  `terrier/react_17` (стоячие, нахмуренные брови, лапа), у хомяка —
  `hamster/react_20` (V-образные брови, лапы скрещены). Все три по
  высоте совпадают с базовой стойкой (POSE_SCALE не требуется). Старый
  `react_14` хомяка остался как запасной кадр для недостижимой позы
  scared.
- **RPG-экономика с анти-фармом**: клик-XP ограничен 30 XP за 10 минут
  (скользящее окно в `progress._click_xp_win`), чтобы «накликать
  уровень» за минуту было нельзя; фокус-бонус за 25 минут тишины
  сбрасывается любым кликом.

## 5. Настройки (settings.json)

| Ключ | Значение по умолчанию | Описание |
|---|---|---|
| `scale` | 0.4 | размер фигурки, 0.4–2.5 (по умолчанию 0.4 — первая зверушка маленькая, 23.11) |
| `speed` | 1.0 | множитель скорости ходьбы |
| `pet` | hamster | папка питомца в assets/sprites (hamster/terrier/cat) |
| `pos_x` | null | X последнего положения (Y не хранится: старт — всегда панель задач) |
| `progress` | {} | RPG-прогресс: xp, счётчики, ачивки, стрик (см. progress.DEFAULTS) |

## 6. Разработка

- **Зависимости**: Python 3.13 (Store), пакеты в `C:\pylib`
  (`sys.path.insert(0, r'C:\pylib')` в первых строках): PySide6-Essentials,
  numpy, Pillow, scipy (только make_sprites).
- **Сборка**: `_rebuild.bat` → PyInstaller **onedir** (`ZverushkaDir.spec`):
  `dist\Zverushka\Zverushka.exe` + `_internal\` + копия `assets\` рядом с
  exe (фразы/спрайты остаются редактируемыми). `settings.json` перед
  сборкой резервируется в `%TEMP%\zverushka_settings_backup.json` и
  возвращается после (PyInstaller `--clean` пересоздаёт папку `dist`
  целиком). Поиск assets в рантайме — `sprites.assets_root()`: рядом с
  exe → `_internal\assets` → `sys._MEIPASS` (onefile). Onefile-спеки
  `Zverushka.spec` / `ZverushkaDbg.spec` сохранены как архивные.
  Если EXE запущен — сначала `_close_pet.py`.
- **Чистый дистрибутив для передачи**: `_make_share.bat` →
  `dist_share\Zverushka\` + `dist_share\Zverushka.zip` — копия основной
  сборки БЕЗ `settings.json` (чужой прогресс не передаётся; у получателя
  файл создастся при первом выходе, масштаб по умолчанию 0.4).
- **Тесты**: `python _verify_states.py`, `python _verify_new.py`,
  `python _verify_pets.py`, `python _verify_progress.py` и
  `python _smoke_test.py` (все — тем же Python 3.13; offscreen, окно не
  появляется).
- **Новый питомец**: сгенерировать листы (мастер-референс + листы
  walk 1×4, sit 1×2, react_a/b 1×4, react_c 1×2, icon) в
  `assets/raw_<имя>/`, затем `python _cut_new_pet.py <имя>` — нарежет,
  скопирует `part_*` от хомяка и сделает иконку. Минимум для работы —
  кадры `walk_0`, `sit_0`. (Старый пайплайн хомяка — `make_sprites.py`.)
  Если отдельная поза выбивается по размеру — добавьте её в `POSE_SCALE`
  (sprites.py) и проверьте линейкой `_pose_grid.py`.
- **Новые фразы**: просто добавьте строки в `assets/sprites/phrases.json`.
